## Конфигурация при компиляции

Все переопределяются через `#define` ПЕРЕД `#include "logger.h"`.

| Define | По умолчанию | Смысл |
|---|---|---|
| `LOGGER_BUFFER_CAPACITY` | `256` | ёмкость статического буфера записей, максимум 256 |
| `LOGGER_MARK_MAX_IDS` | `32` | сколько разных `mark_id` отслеживает статистика частоты меток |
| `LOGGER_BUFFER_SECTION_ATTR` | пусто | атрибут компилятора для статического буфера логов, например `__attribute__((section(".buffer")))` - разместить буфер в конкретной секции ОЗУ (например, под DMA) |
| `LOGGER_MARK_TIME_SOURCE` | `LOGGER_MARK_TIME_SYSTICK_MS` | источник времени для статистики `LOGGER_Mark()`/`LOGGER_GetMarkFrequency()` - `..._SYSTICK_MS` (HAL_GetTick(), везде), `..._DWT_MS`/`..._DWT_US` (аппаратный DWT->CYCCNT, точнее, только Cortex-M3/M4/M7). НЕ влияет на systick, попадающий в сами записи логов/буфер - тот всегда HAL_GetTick() |
| `LOGGER_NO_ITM` | не определён | на ядрах без блока ITM (Cortex-M0/M0+) - убирает из сборки вывод через ITM_SendChar и делает `console_fn` ОБЯЗАТЕЛЬНОЙ (`LOGGER_Init()` вернёт `HAL_ERROR` без неё) |

## Типы

### `LOGGER_Priority_t`

3 уровня приоритета лога:

| Значение | Смысл |
|---|---|
| `LOGGER_PRIORITY_LOW` | низкий приоритет - как правило, реже пишется в память |
| `LOGGER_PRIORITY_MEDIUM` | средний приоритет |
| `LOGGER_PRIORITY_HIGH` | высокий приоритет - как правило, чаще пишется в память |

### `LOGGER_LogEntry_t`

Одна запись таблицы кодов логов (заполняется пользователем в `logger_codes.h`).

| Поле | Тип | Описание |
|---|---|---|
| `code` | `uint16_t` | уникальный код лога, HEX, вне диапазона `0x0000-0x00FF` (зарезервирован). Таблица должна быть отсортирована по этому полю по возрастанию, без повторов |
| `priority` | `LOGGER_Priority_t` | приоритет данного кода |
| `description` | `const char*` | короткое описание для консоли/SWO (рекомендуется 32-64 символа, жёсткий предел `LOGGER_MAX_DESCRIPTION_LENGTH`); в энергонезависимую память не попадает |

### `LOGGER_Record_t`

Формат одной записи в буфере и в данных, переданных в `LOGGER_MemoryWriteFn_t` (16 байт, без выравнивающих "дыр"):

| Поле | Тип | Описание |
|---|---|---|
| `code` | `uint16_t` | код лога (как в `LOGGER_LogTable`) |
| `source_id` | `uint16_t` | идентификатор источника события, из `LOGGER_Log()` |
| `value` | `int32_t` | значение переменной, переданное в `LOGGER_Log()` |
| `systick` | `uint32_t` | `HAL_GetTick()` на момент события, мс с момента старта |
| `rtc_time` | `uint32_t` | показание RTC на момент события, либо 0 (см. `rtc_time_fn`) |

### `LOGGER_MemoryWriteFn_t`

```c
typedef void (*LOGGER_MemoryWriteFn_t)(void *context, const uint8_t *data, uint32_t length_bytes);
```

Функция сохранения накопленных логов в энергонезависимую память. Вызывается, когда по текущему максимальному приоритету буфера достигнут настроенный порог. `data` указывает на массив `LOGGER_Record_t` подряд, валиден только на время вызова.

### `LOGGER_ConsoleWriteFn_t`

```c
typedef void (*LOGGER_ConsoleWriteFn_t)(void *context, uint16_t code, uint16_t source_id,
                                         LOGGER_Priority_t priority, int32_t value,
                                         uint32_t systick, uint32_t rtc_time,
                                         const char *description);
```

Функция вывода одной записи лога в консоль, заменяет вывод по умолчанию в SWO. `description` равен `NULL`, если код не найден ни в пользовательской, ни в служебной таблице.

### `LOGGER_RtcTimeFn_t`

```c
typedef uint32_t (*LOGGER_RtcTimeFn_t)(void *context);
```

Функция чтения текущего времени RTC, вызывается на каждый `LOGGER_Log()`/`LOGGER_Mark()`, только если задана в `LOGGER_Init()`. Формат возвращаемого значения - на усмотрение пользователя, библиотека его не интерпретирует.

### `LOGGER_Config_t`

Конфигурация `LOGGER_Init()`.

| Поле | Тип | Описание |
|---|---|---|
| `write_fn` | `LOGGER_MemoryWriteFn_t` | функция записи в память. `NULL` - буферизация выключена |
| `write_context` | `void*` | передаётся первым аргументом в `write_fn`. Может быть `NULL` |
| `console_fn` | `LOGGER_ConsoleWriteFn_t` | функция вывода в консоль. `NULL` - вывод по умолчанию в SWO |
| `console_context` | `void*` | передаётся первым аргументом в `console_fn`. Может быть `NULL` |
| `rtc_time_fn` | `LOGGER_RtcTimeFn_t` | функция чтения RTC. `NULL` - поле `rtc_time` всегда 0 |
| `rtc_context` | `void*` | передаётся первым аргументом в `rtc_time_fn`. Может быть `NULL` |
| `threshold_low` | `uint8_t` | порог сброса буфера по низкому приоритету, 1..255 |
| `threshold_medium` | `uint8_t` | порог сброса буфера по среднему приоритету, 1..255 |
| `threshold_high` | `uint8_t` | порог сброса буфера по высокому приоритету, 1..255 |

Пороги учитываются, только если `write_fn != NULL`. Рекомендуется `threshold_high <= threshold_medium <= threshold_low` - логи более высокого приоритета обычно должны попадать в память чаще.

## Служебные коды библиотеки

Диапазон `0x0000-0x00FF` зарезервирован под служебные логи самой библиотеки - `LOGGER_Init()` отклонит пользовательскую таблицу кодов, если в ней есть код из этого диапазона.

| Код | Константа | Когда происходит | Буферизуется? |
|---|---|---|---|
| `0x0001` | `LOGGER_INTERNAL_CODE_INIT` | успешное завершение `LOGGER_Init()`; `value` = размер пользовательской таблицы кодов | нет - только вывод |
| `0x0002` | `LOGGER_INTERNAL_CODE_FLUSH` | буфер сброшен в `write_fn`; `value` = количество записей в сбросе | нет - только вывод (иначе рекурсия) |
| `0x0003` | `LOGGER_INTERNAL_CODE_MARK` | вызвана `LOGGER_Mark()` | да - как обычный лог |

## Инициализация

### `HAL_StatusTypeDef LOGGER_Init(const LOGGER_Config_t *config)`

Проверяет корректность таблицы кодов (`logger_codes.h` - отсортирована по возрастанию, без повторов, без кодов из зарезервированного диапазона `0x0000-0x00FF`, приоритеты и длины описаний корректны) и конфигурации, применяет колбэки и пороги буферизации. Вся валидация выполняется здесь, один раз, чтобы `LOGGER_Log()` не делал проверок в рантайме. По завершении логирует служебное событие `LOGGER_INTERNAL_CODE_INIT` (только вывод). Если выбран источник времени статистики меток DWT (см. `LOGGER_MARK_TIME_SOURCE`), сама включает аппаратный счётчик тактов ядра.

Необязательна - без вызова `LOGGER_Init()` (или до него) `LOGGER_Log()` работает в минимальном режиме "только вывод в SWO" (либо не выводится вовсе, если определён `LOGGER_NO_ITM` и `console_fn` не задана). Повторный вызов сначала сбрасывает в память уже накопленный буфер (если буферизация уже была включена), затем применяет новую конфигурацию.

Возвращает `HAL_OK`; `HAL_ERROR` - если `config == NULL`, таблица кодов пуста / не отсортирована / содержит повтор кода / содержит код из зарезервированного диапазона / некорректный приоритет / слишком длинное описание, либо (при заданном `write_fn`) один из порогов равен 0 или превышает `LOGGER_BUFFER_CAPACITY`, либо (при `LOGGER_NO_ITM`) `console_fn == NULL`.

## Операционные функции

### `void LOGGER_Log(uint16_t code, uint16_t source_id, int32_t value)`

Главная горячая функция - логирует событие: выводит его в консоль/SWO (вместе с автоматической меткой времени - SysTick и, если настроен, RTC) и, если включена буферизация, добавляет в буфер; также обновляет статистику частоты вызова этого кода (см. `LOGGER_GetCodeFrequency()`). Оптимизирована по скорости выполнения, не делает проверок конфигурации в рантайме.

`source_id` - идентификатор конкретного экземпляра/источника события (какой именно канал/устройство вызвал лог), если не нужен - передавайте 0.

Если `code` отсутствует в таблице кодов (пользовательской или служебной) - запись всё равно выводится в консоль/SWO (с `description == NULL`, приоритет трактуется как `LOGGER_PRIORITY_HIGH` только для целей вывода), но не буферизуется и не учитывается в статистике частоты.

### `HAL_StatusTypeDef LOGGER_Flush(void)`

Немедленно записывает накопленный буфер в память через `write_fn`, не дожидаясь достижения порога. Полезно перед переходом в сон/перед обновлением прошивки.

Возвращает `HAL_OK` - буфер пуст либо успешно сброшен; `HAL_ERROR` - буферизация не включена (`LOGGER_Init()` не вызывался или `write_fn == NULL`).

### `HAL_StatusTypeDef LOGGER_EmergencySave(void)`

Как `LOGGER_Flush()`, немедленно записывает буфер в память через `write_fn`, но НЕ логирует служебное событие `LOGGER_INTERNAL_CODE_FLUSH` о самом сбросе - минимум операций на аварийном пути. Предназначена для вызова непосредственно перед программной перезагрузкой или при обнаружении ожидаемой потери питания (например, в обработчике PVD/сторожевого таймера перед сбросом).

Возвращает `HAL_OK` - буфер пуст либо успешно сохранён; `HAL_ERROR` - буферизация не включена (`LOGGER_Init()` не вызывался или `write_fn == NULL`).

## Временные метки

### `void LOGGER_Mark(uint16_t mark_id)`

Фиксирует факт прохождения контрольной точки в коде - лёгкий способ трассировки порядка выполнения без привязки к таблице кодов пользователя. Эквивалентно `LOGGER_Log(LOGGER_INTERNAL_CODE_MARK, mark_id, (int32_t)mark_id)` + обновление статистики вызовов для `LOGGER_GetMarkFrequency()`.

Статистика вызовов ведётся, только если `mark_id < LOGGER_MARK_MAX_IDS` (иначе лог всё равно происходит, просто без статистики). Источник времени статистики настраивается через `LOGGER_MARK_TIME_SOURCE` (см. раздел "Конфигурация при компиляции") - не влияет на systick, попадающий в сам записанный лог.

### `HAL_StatusTypeDef LOGGER_GetMarkFrequency(uint16_t mark_id, float *out_frequency)`

Вычисляет среднюю частоту вызова конкретной метки (вызовов в секунду) по накопленной статистике. Деление с плавающей точкой выполняется только здесь, по явному запросу - не в `LOGGER_Mark()`, чтобы не нагружать горячий путь.

Возвращает `HAL_OK` - частота посчитана; `HAL_ERROR` - `mark_id >= LOGGER_MARK_MAX_IDS`, `out_frequency == NULL`, либо метка вызывалась ещё меньше 2 раз (нет интервала для расчёта).

## Статистика частоты обычных кодов

### `HAL_StatusTypeDef LOGGER_GetCodeFrequency(uint16_t code, float *out_frequency)`

Тот же расчёт средней частоты (вызовов в секунду), что и `LOGGER_GetMarkFrequency()`, но для обычного кода из пользовательской таблицы (`logger_codes.h`), а не для метки. Статистика (кол-во вызовов, первый/последний `HAL_GetTick()`) обновляется автоматически на каждый `LOGGER_Log()` с известным кодом, независимо от буферизации - никакого дополнительного кода в проекте не требуется. Позволяет находить "болтливые" коды логов без ручного счётчика.

Возвращает `HAL_OK` - частота посчитана; `HAL_ERROR` - `out_frequency == NULL`, `code` отсутствует в пользовательской таблице, либо код вызывался ещё меньше 2 раз.

## Разбор дампа памяти

Функции и тип ниже - из `log_decoder.h`, хостовая часть (ПК/сервер). Не зависят от встраиваемой части и не собираются вместе с ней - общий только `logger_codes.h`.

### `LOGDEC_DecodedRecord_t`

Результат разбора одной `LOGGER_Record_t` - сырые поля записи плюс уже подставленные приоритет и описание из таблицы кодов.

| Поле | Тип | Описание |
|---|---|---|
| `code` | `uint16_t` | код лога, как в дампе памяти |
| `source_id` | `uint16_t` | идентификатор источника события |
| `value` | `int32_t` | значение переменной |
| `systick` | `uint32_t` | SysTick на момент события |
| `rtc_time` | `uint32_t` | показание RTC на момент события, либо 0 |
| `priority` | `LOGGER_Priority_t` | приоритет из таблицы кодов; `LOGGER_PRIORITY_HIGH`, если код не найден |
| `description` | `const char*` | описание из таблицы кодов; `NULL`, если код не найден ни в одной таблице |

### `bool LOGDEC_Decode(const uint8_t *data, size_t data_length, LOGDEC_DecodedRecord_t *out_records, size_t out_capacity, size_t *out_count)`

Разбирает сырой дамп памяти (массив `LOGGER_Record_t` подряд) целиком в предоставленный буфер `out_records`. "Всё или ничего": если `out_capacity` не хватает на все записи дампа - функция возвращает `false` и не пишет в `out_records` частично.

Возвращает `true` - дамп полностью разобран, `out_records`/`*out_count` (если не `NULL`) заполнены; `false` - `data`/`out_records == NULL`, `data_length` не кратна `sizeof(LOGGER_Record_t)` (повреждённый/обрезанный дамп), либо `out_capacity` не хватает.

### `const char *LOGDEC_GetDescription(uint16_t code)`

Точечный поиск текстового описания по коду - из пользовательской таблицы (`logger_codes.h`) либо, для диапазона `0x0000-0x00FF`, из служебной таблицы библиотеки. Возвращает `NULL`, если код не найден ни в одной из таблиц.

### `bool LOGDEC_GetPriority(uint16_t code, LOGGER_Priority_t *out_priority)`

Точечный поиск приоритета по коду, из тех же таблиц, что и `LOGDEC_GetDescription()`. Возвращает `true` и заполняет `*out_priority`, если код найден; `false` - если `out_priority == NULL` либо код не найден ни в одной таблице.

## Постфактум-статистика частоты

Хостовый аналог `LOGGER_GetCodeFrequency()`/`LOGGER_GetMarkFrequency()` - считается сразу по всему массиву записей, разобранному `LOGDEC_Decode()`, а не в реальном времени. Обе функции, как и `LOGDEC_Decode()`, "всё или ничего": если `out_capacity` не хватает на все различные коды/метки - возвращают `false` и не пишут в `out_stats`.

### `bool LOGDEC_ComputeCodeStats(const LOGDEC_DecodedRecord_t *records, size_t record_count, LOGDEC_CodeStats_t *out_stats, size_t out_capacity, size_t *out_count)`

Статистика по каждому отдельному коду в `records` (кроме `LOGGER_INTERNAL_CODE_MARK` - см. `LOGDEC_ComputeMarkStats()`). `LOGDEC_CodeStats_t`: `code`, `call_count`, `first_systick`, `last_systick`, `frequency_hz` (0.0f, если данных недостаточно).

### `bool LOGDEC_ComputeMarkStats(const LOGDEC_DecodedRecord_t *records, size_t record_count, LOGDEC_MarkStats_t *out_stats, size_t out_capacity, size_t *out_count)`

Статистика по каждой отдельной метке (`LOGGER_Mark(mark_id)`) - находит записи с кодом `LOGGER_INTERNAL_CODE_MARK` и агрегирует их по `source_id` (= `mark_id`). `LOGDEC_MarkStats_t`: `mark_id`, `call_count`, `first_systick`, `last_systick`, `frequency_hz`.

## Адресные пространства и интеграция зависимых библиотек

Описано подробно в шапке `logger_codes.h`. Старший байт кода разбит на 4 категории по возрастанию адреса:

| Диапазон | Категория |
|---|---|
| `0x00xx-0x3Fxx` | СИСТЕМА и внутренние алгоритмы проекта |
| `0x40xx-0x7Fxx` | ПЕРИФЕРИЯ - интерфейсы МК (SPI, CAN, I2C, UART, ...) |
| `0x80xx-0xDFxx` | ВНЕШНИЕ УСТРОЙСТВА/ДАТЧИКИ, подключённые через периферию |
| `0xE0xx-0xFFxx` | РЕЗЕРВ |

Каждая логическая группа кодов (в том числе собственные группы проекта - пример `SYSTEM` в категории 1) выражается триадой define:

| Define | Смысл |
|---|---|
| `LOG_ADDR_<ИМЯ>` | адресное пространство группы - старший байт кода (`0xNN`) |
| `LOG_OFFSET_<ИМЯ>_<СОБЫТИЕ>` | номер события внутри группы - младший байт кода (`0xNN`) |
| `LOG_CODE_<ИМЯ>_<СОБЫТИЕ>` | итоговый 16-битный код - `(LOG_ADDR_<ИМЯ> << 8) \| LOG_OFFSET_<ИМЯ>_<СОБЫТИЕ>`, используется в `LOGGER_LogTable` |

Если логировать хочет зависимая библиотека - её блок (все три уровня define + записи таблицы) оборачивается в `#ifdef LOGGER_ENABLE_<ИМЯ>` / `#endif` внутри `logger_codes.h`, и она использует только выданные ей `LOG_CODE_<ИМЯ>_<СОБЫТИЕ>` - никогда числовой код напрямую. Никаких кодов "про запас" под несуществующие библиотеки не держим - блок появляется только когда зависимая библиотека подтвердила полный список своих событий. Полный список уже подключаемых библиотек - в справочной секции в самом начале `logger_codes.h` (сразу после шапки).

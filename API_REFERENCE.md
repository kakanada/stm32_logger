## Типы

### `LOGGER_Priority_t`

3 уровня приоритета лога:

| Значение | Смысл |
|---|---|
| `LOGGER_PRIORITY_LOW` | низкий приоритет - как правило, реже пишется в память |
| `LOGGER_PRIORITY_MEDIUM` | средний приоритет |
| `LOGGER_PRIORITY_HIGH` | высокий приоритет - как правило, чаще пишется в память |

### `LOGGER_LogEntry_t`

Одна запись таблицы кодов логов (заполняется пользователем в `logger_codes.h`).

| Поле | Тип | Описание |
|---|---|---|
| `code` | `uint16_t` | уникальный код лога, HEX, вне диапазона `0x0000-0x00FF` (зарезервирован). Таблица должна быть отсортирована по этому полю по возрастанию, без повторов |
| `priority` | `LOGGER_Priority_t` | приоритет данного кода |
| `description` | `const char*` | короткое описание для консоли/SWO (рекомендуется 32-64 символа, жёсткий предел `LOGGER_MAX_DESCRIPTION_LENGTH`); в энергонезависимую память не попадает |

### `LOGGER_Record_t`

Формат одной записи в буфере и в данных, переданных в `LOGGER_MemoryWriteFn_t` (16 байт, без
выравнивающих "дыр"):

| Поле | Тип | Описание |
|---|---|---|
| `code` | `uint16_t` | код лога (как в `LOGGER_LogTable`) |
| `source_id` | `uint16_t` | идентификатор источника события, из `LOGGER_Log()` |
| `value` | `int32_t` | значение переменной, переданное в `LOGGER_Log()` |
| `systick` | `uint32_t` | `HAL_GetTick()` на момент события, мс с момента старта |
| `rtc_time` | `uint32_t` | показание RTC на момент события, либо 0 (см. `rtc_time_fn`) |

### `LOGGER_MemoryWriteFn_t`

```c
typedef void (*LOGGER_MemoryWriteFn_t)(void *context, const uint8_t *data, uint32_t length_bytes);
```

Функция сохранения накопленных логов в энергонезависимую память. Вызывается, когда по текущему
максимальному приоритету буфера достигнут настроенный порог. `data` указывает на массив
`LOGGER_Record_t` подряд, валиден только на время вызова.

### `LOGGER_ConsoleWriteFn_t`

```c
typedef void (*LOGGER_ConsoleWriteFn_t)(void *context, uint16_t code, uint16_t source_id,
                                         LOGGER_Priority_t priority, int32_t value,
                                         uint32_t systick, uint32_t rtc_time,
                                         const char *description);
```

Функция вывода одной записи лога в консоль, заменяет вывод по умолчанию в SWO. `description`
равен `NULL`, если код не найден ни в пользовательской, ни в служебной таблице.

### `LOGGER_RtcTimeFn_t`

```c
typedef uint32_t (*LOGGER_RtcTimeFn_t)(void *context);
```

Функция чтения текущего времени RTC, вызывается на каждый `LOGGER_Log()`/`LOGGER_Mark()`,
только если задана в `LOGGER_Init()`. Формат возвращаемого значения - на усмотрение
пользователя, библиотека его не интерпретирует.

### `LOGGER_Config_t`

Конфигурация `LOGGER_Init()`.

| Поле | Тип | Описание |
|---|---|---|
| `write_fn` | `LOGGER_MemoryWriteFn_t` | функция записи в память. `NULL` - буферизация выключена |
| `write_context` | `void*` | передаётся первым аргументом в `write_fn`. Может быть `NULL` |
| `console_fn` | `LOGGER_ConsoleWriteFn_t` | функция вывода в консоль. `NULL` - вывод по умолчанию в SWO |
| `console_context` | `void*` | передаётся первым аргументом в `console_fn`. Может быть `NULL` |
| `rtc_time_fn` | `LOGGER_RtcTimeFn_t` | функция чтения RTC. `NULL` - поле `rtc_time` всегда 0 |
| `rtc_context` | `void*` | передаётся первым аргументом в `rtc_time_fn`. Может быть `NULL` |
| `threshold_low` | `uint8_t` | порог сброса буфера по низкому приоритету, 1..255 |
| `threshold_medium` | `uint8_t` | порог сброса буфера по среднему приоритету, 1..255 |
| `threshold_high` | `uint8_t` | порог сброса буфера по высокому приоритету, 1..255 |

Пороги учитываются, только если `write_fn != NULL`. Рекомендуется
`threshold_high <= threshold_medium <= threshold_low` - логи более высокого приоритета обычно
должны попадать в память чаще.

## Служебные коды библиотеки

Диапазон `0x0000-0x00FF` зарезервирован под служебные логи самой библиотеки -
`LOGGER_Init()` отклонит пользовательскую таблицу кодов, если в ней есть код из этого
диапазона.

| Код | Константа | Когда происходит | Буферизуется? |
|---|---|---|---|
| `0x0001` | `LOGGER_INTERNAL_CODE_INIT` | успешное завершение `LOGGER_Init()`; `value` = размер пользовательской таблицы кодов | нет - только вывод |
| `0x0002` | `LOGGER_INTERNAL_CODE_FLUSH` | буфер сброшен в `write_fn`; `value` = количество записей в сбросе | нет - только вывод (иначе рекурсия) |
| `0x0003` | `LOGGER_INTERNAL_CODE_MARK` | вызвана `LOGGER_Mark()` | да - как обычный лог |

## Инициализация

### `HAL_StatusTypeDef LOGGER_Init(const LOGGER_Config_t *config)`

Проверяет корректность таблицы кодов (`logger_codes.h` - отсортирована по возрастанию, без
повторов, без кодов из зарезервированного диапазона `0x0000-0x00FF`, приоритеты и длины
описаний корректны) и конфигурации, применяет колбэки и пороги буферизации. Вся валидация
выполняется здесь, один раз, чтобы `LOGGER_Log()` не делал проверок в рантайме. По завершении
логирует служебное событие `LOGGER_INTERNAL_CODE_INIT` (только вывод).

Необязательна - без вызова `LOGGER_Init()` (или до него) `LOGGER_Log()` работает в минимальном
режиме "только вывод в SWO". Повторный вызов сначала сбрасывает в память уже накопленный буфер
(если буферизация уже была включена), затем применяет новую конфигурацию.

Возвращает `HAL_OK`; `HAL_ERROR` - если `config == NULL`, таблица кодов пуста / не
отсортирована / содержит повтор кода / содержит код из зарезервированного диапазона /
некорректный приоритет / слишком длинное описание, либо (при заданном `write_fn`) один из
порогов равен 0 или превышает `LOGGER_BUFFER_CAPACITY`.

## Операционные функции

### `void LOGGER_Log(uint16_t code, uint16_t source_id, int32_t value)`

Главная горячая функция - логирует событие: выводит его в консоль/SWO (вместе с
автоматической меткой времени - SysTick и, если настроен, RTC) и, если включена буферизация,
добавляет в буфер. Оптимизирована по скорости выполнения, не делает проверок конфигурации в
рантайме.

`source_id` - идентификатор конкретного экземпляра/источника события (какой именно канал/
устройство вызвал лог), если не нужен - передавайте 0.

Если `code` отсутствует в таблице кодов (пользовательской или служебной) - запись всё равно
выводится в консоль/SWO (с `description == NULL`, приоритет трактуется как
`LOGGER_PRIORITY_HIGH` только для целей вывода), но не буферизуется.

### `HAL_StatusTypeDef LOGGER_Flush(void)`

Немедленно записывает накопленный буфер в память через `write_fn`, не дожидаясь достижения
порога. Полезно перед переходом в сон/перед обновлением прошивки.

Возвращает `HAL_OK` - буфер пуст либо успешно сброшен; `HAL_ERROR` - буферизация не включена
(`LOGGER_Init()` не вызывался или `write_fn == NULL`).

## Временные метки

### `void LOGGER_Mark(uint16_t mark_id)`

Фиксирует факт прохождения контрольной точки в коде - лёгкий способ трассировки порядка
выполнения без привязки к таблице кодов пользователя. Эквивалентно
`LOGGER_Log(LOGGER_INTERNAL_CODE_MARK, mark_id, (int32_t)mark_id)` + обновление статистики
вызовов для `LOGGER_GetMarkFrequency()`.

Статистика вызовов ведётся, только если `mark_id < LOGGER_MARK_MAX_IDS` (иначе лог всё равно
происходит, просто без статистики).

### `HAL_StatusTypeDef LOGGER_GetMarkFrequency(uint16_t mark_id, float *out_frequency)`

Вычисляет среднюю частоту вызова конкретной метки (вызовов в секунду) по накопленной
статистике. Деление с плавающей точкой выполняется только здесь, по явному запросу - не в
`LOGGER_Mark()`, чтобы не нагружать горячий путь.

Возвращает `HAL_OK` - частота посчитана; `HAL_ERROR` - `mark_id >= LOGGER_MARK_MAX_IDS`,
`out_frequency == NULL`, либо метка вызывалась ещё меньше 2 раз (нет интервала для расчёта).

# logger — справочник по API

Дисклеймер: при расхождениях с [logger.h](logger.h) ориентируйтесь на `.h`, он первичен,
этот справочник - его сжатый пересказ.

## Типы

### `LOGGER_Priority_t`

3 уровня приоритета лога:

| Значение | Смысл |
|---|---|
| `LOGGER_PRIORITY_LOW` | низкий приоритет - как правило, реже пишется в память |
| `LOGGER_PRIORITY_MEDIUM` | средний приоритет |
| `LOGGER_PRIORITY_HIGH` | высокий приоритет - как правило, чаще пишется в память |

### `LOGGER_LogEntry_t`

Одна запись таблицы кодов логов (заполняется пользователем в `logger_codes.h`).

| Поле | Тип | Описание |
|---|---|---|
| `code` | `uint32_t` | уникальный код лога, HEX. Таблица должна быть отсортирована по этому полю по возрастанию, без повторов |
| `priority` | `LOGGER_Priority_t` | приоритет данного кода |
| `description` | `const char*` | короткое описание для консоли/SWO (рекомендуется 32-64 символа, жёсткий предел `LOGGER_MAX_DESCRIPTION_LENGTH`); в энергонезависимую память не попадает |

### `LOGGER_Record_t`

Формат одной записи в буфере и в данных, переданных в `LOGGER_MemoryWriteFn_t` (8 байт, без
выравнивающих "дыр"):

| Поле | Тип | Описание |
|---|---|---|
| `code` | `uint32_t` | код лога (как в `LOGGER_LogTable`) |
| `value` | `int32_t` | значение переменной, переданное в `LOGGER_Log()` |

### `LOGGER_MemoryWriteFn_t`

```c
typedef void (*LOGGER_MemoryWriteFn_t)(void *context, const uint8_t *data, uint32_t length_bytes);
```

Функция сохранения накопленных логов в энергонезависимую память. Вызывается, когда по текущему
максимальному приоритету буфера достигнут настроенный порог. `data` указывает на массив
`LOGGER_Record_t` подряд, валиден только на время вызова.

### `LOGGER_ConsoleWriteFn_t`

```c
typedef void (*LOGGER_ConsoleWriteFn_t)(void *context, uint32_t code, LOGGER_Priority_t priority,
                                         int32_t value, const char *description);
```

Функция вывода одной записи лога в консоль, заменяет вывод по умолчанию в SWO. `description`
равен `NULL`, если код не найден в таблице.

### `LOGGER_Config_t`

Конфигурация `LOGGER_Init()`.

| Поле | Тип | Описание |
|---|---|---|
| `write_fn` | `LOGGER_MemoryWriteFn_t` | функция записи в память. `NULL` - буферизация выключена |
| `write_context` | `void*` | передаётся первым аргументом в `write_fn`. Может быть `NULL` |
| `console_fn` | `LOGGER_ConsoleWriteFn_t` | функция вывода в консоль. `NULL` - вывод по умолчанию в SWO |
| `console_context` | `void*` | передаётся первым аргументом в `console_fn`. Может быть `NULL` |
| `threshold_low` | `uint8_t` | порог сброса буфера по низкому приоритету, 1..255 |
| `threshold_medium` | `uint8_t` | порог сброса буфера по среднему приоритету, 1..255 |
| `threshold_high` | `uint8_t` | порог сброса буфера по высокому приоритету, 1..255 |

Пороги учитываются, только если `write_fn != NULL`. Рекомендуется
`threshold_high <= threshold_medium <= threshold_low` - логи более высокого приоритета обычно
должны попадать в память чаще.

## Инициализация

### `HAL_StatusTypeDef LOGGER_Init(const LOGGER_Config_t *config)`

Проверяет корректность таблицы кодов (`logger_codes.h` - отсортирована по возрастанию, без
повторов, приоритеты и длины описаний корректны) и конфигурации, применяет колбэки и пороги
буферизации. Вся валидация выполняется здесь, один раз, чтобы `LOGGER_Log()` не делал проверок
в рантайме.

Необязательна - без вызова `LOGGER_Init()` (или до него) `LOGGER_Log()` работает в минимальном
режиме "только вывод в SWO". Повторный вызов сначала сбрасывает в память уже накопленный буфер
(если буферизация уже была включена), затем применяет новую конфигурацию.

Возвращает `HAL_OK`; `HAL_ERROR` - если `config == NULL`, таблица кодов пуста / не
отсортирована / содержит повтор кода / содержит некорректный приоритет / слишком длинное
описание, либо (при заданном `write_fn`) один из порогов равен 0 или превышает
`LOGGER_BUFFER_CAPACITY`.

## Операционные функции

### `void LOGGER_Log(uint32_t code, int32_t value)`

Главная горячая функция - логирует событие: выводит его в консоль/SWO и, если включена
буферизация, добавляет в буфер. Оптимизирована по скорости выполнения, не делает проверок
конфигурации в рантайме.

Если `code` отсутствует в таблице кодов - запись всё равно выводится в консоль/SWO (с
`description == NULL`, приоритет трактуется как `LOGGER_PRIORITY_HIGH` только для целей
вывода), но не буферизуется.

### `HAL_StatusTypeDef LOGGER_Flush(void)`

Немедленно записывает накопленный буфер в память через `write_fn`, не дожидаясь достижения
порога. Полезно перед переходом в сон/перед обновлением прошивки.

Возвращает `HAL_OK` - буфер пуст либо успешно сброшен; `HAL_ERROR` - буферизация не включена
(`LOGGER_Init()` не вызывался или `write_fn == NULL`).

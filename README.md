# logger

Библиотека кодового логирования для STM32 для систем из одного или нескольких микроконтроллеров: события логируются по числовому коду с приоритетом, источником и значением, выводятся в отладочный интерфейс и сохраняются в энергонезависимую память; контроллеры без собственной памяти пересылают свои логи основному по любому интерфейсу; на ПК дамп разбирается обратно в читаемые записи.

## Возможности

- Одна функция логирования события `LOGGER_Log(code, source_id, value)` с приоритетами, метками времени (SysTick и опционально RTC) и общей таблицей кодов проекта, в которую подключаются коды зависимых библиотек.
- Три приёмника логов в основном контроллере: потоковый вывод (SWO, UART, COM), бинарная запись в энергонезависимую память и читаемый текстовый журнал фиксированной длины (для FAT на SD или USB), каждый со своим порогом приоритета.
- Приём логов от до 255 второстепенных контроллеров в общий журнал с признаком источника, с учётом потерь на линии; интерфейс связи (CAN, UART, SPI, I2C) выбирает пользователь через указатели на функции.
- Разбор дампа памяти на ПК с подстановкой приоритетов и описаний.

## Варианты

| Папка | За что отвечает | Подробности |
|---|---|---|
| `device_master` | основной контроллер: пишет собственные логи, принимает логи slave, сохраняет в память и в текстовый журнал | [README](device_master/README.md) |
| `device_slave` | второстепенный контроллер без хранилища: выводит логи локально и отправляет master через вашу функцию отправки | [README](device_slave/README.md) |
| `host` | ПК или сервер: разбор дампа энергонезависимой памяти master | [README](host/README.md) |

Пользователь копирует в проект только папку нужной роли. Файлы `logger_types.h` и `logger_codes.h` в трёх папках одинаковы: при изменении таблицы кодов обновляйте их во всех ролях.

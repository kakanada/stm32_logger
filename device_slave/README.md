# logger (device_slave)

Роль `device_slave` библиотеки кодового логирования для STM32: второстепенный микроконтроллер без собственного хранилища логов. Он выводит логи в SWO или свою консоль так же, как основной, и одновременно ставит их в небольшую очередь и по мере возможности отправляет master-контроллеру через любой физический интерфейс (CAN, UART, SPI, I2C) - библиотека интерфейс не знает, отправка идёт через указатель на вашу функцию. Рассчитана на маленькие МК (до 128 КБ флеш): без malloc, без буфера сохранения, без статистики и без форматирования текста для файла.

## Возможности

- Тот же вызов, что у master: `LOGGER_Log(code, source_id, value)` - код приложения не меняется при переходе между ролями.
- Вывод каждой записи в SWO по умолчанию или в свою `console_fn` (UART/COM) - в том же читаемом формате, что у master (с описанием из таблицы кодов `logger_codes.h`).
- Отправка master через `send_fn` - любой интерфейс, без подтверждений и обратной связи (шину не нагружаем). Кадр содержит `node_id`, номер `seq`, код, источник и значение; время ставит master в момент прихода.
- До 255 slave на линии, у каждого свой `node_id` (1..255).
- Очередь на `LOGGER_BUFFER_CAPACITY` кадров (по умолчанию 32, 12 байт каждый), отправка из главного цикла (`LOGGER_Process()`), не более `LOGGER_MAX_FRAMES_PER_PROCESS` кадров за вызов - защита от лавины. Если `send_fn` вернула не `HAL_OK`, кадр остаётся в очереди.
- Фильтр `send_min_priority`: например, отправлять master только ошибки, а остальное выводить только локально.
- Потери: при полной очереди запись теряется, но номер `seq` расходуется - master видит разрыв и пишет служебную запись; после освобождения места slave отправляет сводку `LOGGER_INTERNAL_CODE_DROPPED_SUMMARY` с числом потерь.
- Готовые хелперы упаковки кадра (`LOGGER_FramePackRaw()`, `LOGGER_FramePackStream()` с CRC16) в `logger_types.h`.

## Требования к настройке в CubeMX

| Настройка | Значение |
|---|---|
| Debug (SYS -> Debug) | `Serial Wire` - только если нужен вывод в SWO |
| Интерфейс связи с master | настраивается пользователем; библиотека периферию не трогает |

Библиотека сама не занимает никакой периферии: интерфейс отправки целиком в вашей `send_fn`.

## Быстрый старт

Скопируйте в проект файлы папки `device_slave`: `logger.h`, `logger.c`, `logger_types.h`, `logger_codes.h`. В `logger_codes.h` включите группы кодов этого МК (`#define LOGGER_ENABLE_<ИМЯ>` до `#include`). Те же группы должны быть включены в таблице master.

```c
#include "logger.h"
#include "logger_codes.h"

/* Отправка по classic CAN: расширенный id = (node_id << 8) | seq, данные: code(2), source_id(2), value(4). */
static HAL_StatusTypeDef my_can_send(void *context, const LOGGER_Frame_t *f)
{
    uint8_t d[8];
    d[0] = (uint8_t)(f->code);       d[1] = (uint8_t)(f->code >> 8);
    d[2] = (uint8_t)(f->source_id);  d[3] = (uint8_t)(f->source_id >> 8);
    d[4] = (uint8_t)(f->value);      d[5] = (uint8_t)(f->value >> 8);
    d[6] = (uint8_t)(f->value >> 16); d[7] = (uint8_t)(f->value >> 24);
    return my_can_tx((my_can_t *)context, ((uint32_t)f->node_id << 8) | f->seq, d, 8U)
               ? HAL_OK : HAL_BUSY;   /* нет свободного почтового ящика - повторим позже */
}

void app_init(void)
{
    LOGGER_Config_t cfg =
    {
        .node_id           = 7,              /* id этого МК, уникальный на линии */
        .send_fn           = my_can_send,
        .send_context      = &my_can,
        .send_min_priority = LOGGER_PRIORITY_LOW,
        .console_fn        = NULL,           /* NULL - вывод в SWO */
    };
    LOGGER_Init(&cfg);
    LOGGER_Log(LOG_CODE_SYSTEM_START, 0, 0);
}

void app_loop(void)
{
    LOGGER_Process();   /* регулярно из главного цикла */
}
```

`node_id` обычно читается из константы во флеш (адрес, который записывает загрузчик) и передаётся в конфигурацию.

## Интеграция зависимых библиотек

Коды логов зависимых библиотек подключаются так же, как у master: блок `#ifdef LOGGER_ENABLE_<ИМЯ>` в `logger_codes.h` (адрес группы, смещения, записи таблицы, имя группы). Файл `logger_codes.h` во всех трёх ролях идентичен; при изменении таблицы меняйте его во всех папках сразу. Приоритет кода влияет на фильтр `send_min_priority`, а описание - на локальный вывод.

## Честные ограничения

- Ни подтверждений, ни повторной отправки потерянных на шине кадров нет: потеря видна только master по разрыву `seq`.
- Нет таблицы проверки `LOGGER_Init()`: корректность таблицы кодов проверяйте на master (его `LOGGER_Init()` отклонит неверную таблицу) или скриптом `check_descriptions.ps1` из `../device_master`.
- Кадры уходят только из `LOGGER_Process()`: если главный цикл не вызывает её регулярно, очередь переполнится.
- Время ставит master при получении кадра, поэтому оно отличается от момента события на задержку в шине и в очереди slave. Локальный вывод slave использует собственный `HAL_GetTick()`.
- Перезапуск slave начинает нумерацию `seq` с нуля, master может принять это за потерю нескольких кадров.
- На ядрах без ITM (Cortex-M0/M0+) определите `LOGGER_NO_ITM` перед `#include "logger.h"`: вывод в SWO исключается из сборки, и `console_fn` становится обязательной.
- Вызов `LOGGER_Log()` из ISR допустим (короткая критическая секция PRIMASK), `LOGGER_Process()` вызывайте из главного цикла.
